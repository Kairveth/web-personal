API de candidaturas en Salesforce

Recibe candidaturas por REST, valida sus cambios de estado y avisa a un sistema externo cuando una candidatura pasa a entrevista. Aquí está el recorrido completo, con capturas de cada paso.

Recorrido

  1. Crear por API

    Postman envía un POST a /services/apexrest/candidaturas con el identificador externo, el nombre y el estado. La API responde 201.

  2. Comprobar en el registro

    La ficha muestra el estado actual y solo los botones de las transiciones permitidas. Desde Recibida se puede pasar a En revisión o a Descartada.

  3. Leer por identificador externo

    Un GET con IdExterno__c devuelve el estado actual. Los tests comprueban el código de respuesta y el estado.

  4. Pasar a Entrevista

    El trigger valida la transición y encola un Queueable con las candidaturas que acaban de entrar en Entrevista. La llamada externa se hace en el job, no en el trigger.

  5. Enviar el lote

    Un único POST lleva todo el lote. Cada elemento tiene idExterno, nombre y estado.

Qué contiene el repositorio

  • API REST con upsert por identificador externo y códigos 201, 200, 400, 409 y 500.
  • Trigger y handler validan transiciones en before update y encolan en after update.
  • Queueable con reintento un callout por lote y un Finalizer que reencola una vez si falla.
  • Batch RGPD anonimiza las candidaturas cuya fecha de descarte ya venció.
  • Componente de estado LWC en la ficha con los botones de transición permitidos.
  • Colección de Postman nueve peticiones con tests del CRUD y de los errores.

Decisiones

Un callout por lote. Con 200 candidaturas en una transacción, el destino recibe una sola petición.

Las reglas de transición están en el trigger, así se aplican también desde la ficha.

Las credenciales están en Named Credential y External Credential de la org, fuera del repositorio.
